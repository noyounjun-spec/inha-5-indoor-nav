# 데이터 모델

검사 명령은 `node scripts/validate-graph.mjs`다. 데이터(json)를 고치면 반드시 실행한다.

## 관·층 코드

| 관 | 코드 |
|----|------|
| 5북관 | `5N` |
| 5서관 | `5W` |
| 5남관 | `5S` |
| 5동관 | `5E` |

층 코드는 `B1`, `1F`, `2F`, `3F`, `4F`다. 관마다 실제로 있는 층은 도면을 보고 확정한다. 없는 층은 파일을 만들지 않는다.

도면 기준으로 확인한 층(현장 확인 전):

| 관 | B1 | 1F | 2F | 3F | 4F | 비고 |
|----|----|----|----|----|----|------|
| 5N | ○ | ○ | ○ | ○ | ○ | |
| 5W | ✕ | ○ | ○ | ○ | ○ | B1 도면의 위치 그림에서 5서관은 색칠되지 않음. 1F는 복도가 그려져 있지 않아 방 없음 |
| 5S | ○ | ○ | ○ | ○ | ○ | |
| 5E | ○ | ○ | ○ | ○ | ○ | |

## ID 규칙

- **방**: `관-층-호수`, 예: `5S-2F-234`
  - 호수는 관마다 따로 매긴다. 5북관 234호와 5남관 234호는 서로 다른 방이다.
  - 호수에 하이픈이 있으면 `_`로 바꾼다(`234-1` → `234_1`). 원래 표기는 `name`에 적는다.
- **노드**(길 위의 점): `관-층-N번호`, 예: `5S-2F-N012`
- **계단/엘리베이터 그룹**: `관-ST-이름`, `관-EV-이름`, 예: `5S-ST-C`(5남관 가운데 계단)

## 파일: `data/floors/{관}-{층}.json`

파일 하나가 한 관의 한 층이다(예: `5S-2F.json`).
평면도 원본은 층마다 한 장(`floorplans/2F.png`)이고 네 관이 모두 들어 있다. 같은 층의 관별 파일들은 같은 `image`와 `metersPerUnit`을 쓰므로 **좌표 체계가 같다**.

```json
{
  "building": "5S",
  "floor": "2F",
  "level": 2,
  "image": "floorplans/2F.png",
  "metersPerUnit": 0.05,
  "scaleSource": "도면 오른쪽 아래 축척 막대 10m = 200px",
  "nodes": [
    { "id": "5S-2F-N001", "type": "corridor", "x": 120, "y": 340 },
    { "id": "5S-2F-N002", "type": "door", "x": 150, "y": 300 },
    { "id": "5S-2F-N003", "type": "stair", "x": 400, "y": 340, "group": "5S-ST-C", "treadsToNextUp": 22 },
    { "id": "5S-1F-N001", "type": "entrance", "x": 10, "y": 340, "geo": { "lat": 0, "lng": 0 } }
  ],
  "rooms": [
    { "id": "5S-2F-234", "name": "234호", "aliases": ["○○실험실"], "doors": ["5S-2F-N002"] }
  ],
  "edges": [
    { "from": "5S-2F-N001", "to": "5S-2F-N002" },
    { "from": "5S-2F-N001", "to": "5N-2F-N010", "lengthM": 6.5 }
  ],
  "unknown": [
    { "what": "236호 옆 복도 끝", "where": "도면 오른쪽 위", "note": "도면이 잘려 있어 이어지는 길을 알 수 없음" }
  ]
}
```
(위 값은 형식을 보여 주는 예시일 뿐 실제 데이터가 아니다.)

### 필드

| 필드 | 설명 |
|------|------|
| `level` | 물리적 높이(층 단위). B1=0, 1F=1, 2F=2, 3F=3, 4F=4 |
| `metersPerUnit` | 도면 좌표 1단위가 몇 m인지. 축척 막대나 치수를 보고 계산한다 |
| `scaleSource` | 축척을 어디서 구했는지. 구할 수 없으면 `unknown`에 적고 사용자에게 현장 측정을 요청한다 |
| `nodes[].type` | `corridor` 복도 · `junction` 갈림길 · `door` 방 문 · `entrance` 건물 출입구 · `stair` 계단 · `elevator` 엘리베이터 |
| `nodes[].x, y` | 도면 이미지 픽셀 좌표. 원점은 왼쪽 위, x는 오른쪽, y는 아래로 커진다 |
| `nodes[].level` | (선택) 이 노드만 층 높이가 다를 때 쓴다(계단참 등) |
| `nodes[].group` | 계단·엘리베이터는 필수. 같은 group끼리 층 사이가 자동으로 연결된다 |
| `nodes[].treadsToNextUp` | (계단) 바로 위 정차층까지의 계단 칸 수. 모르면 비워 두고 `unknown`에 적는다 |
| `nodes[].geo` | (입구) 위도·경도. GPS로 출발하는 경로에 필요하다 |
| `nodes[].name` | (선택, 입구) 화면에 보일 이름. 예: `"5남관 정문"`. 없으면 `5남관 입구 (1F)`로 표시된다 |
| `rooms[].doors` | 방에 드나드는 노드 목록. 문이 여러 개면 모두 적는다 |
| `edges[]` | 걸어서 이동할 수 있는 두 노드를 잇는다(양방향). 길이는 좌표로 계산한다 |
| `edges[].lengthM` | (선택) 길이를 직접 지정할 때. 다른 파일의 노드와 이을 때 두 파일의 `image`나 `metersPerUnit`이 다르면 필수다 |
| `unknown[]` | 도면에서 확인할 수 없는 방·복도·연결. **추측해서 노드를 만들지 말고 여기에 적는다** |

## 수직 연결(계단·엘리베이터)

- 같은 `group`의 노드끼리 자동으로 연결된다. 층 사이 edge를 직접 적지 않는다.
- **계단**: 높이 순으로 바로 옆 정차층끼리만 연결된다. 칸 수는 아래쪽 노드의 `treadsToNextUp` 값을 쓰고, 값이 없으면 docs/ROUTING.md의 기본값을 쓴다.
- **엘리베이터**: 같은 group의 모든 층끼리 연결된다.

## 5남관 가운데 계단(반 층 어긋남)

5남관 가운데 계단은 다른 관과 **반 층 어긋난 구조**다.
- 계단참처럼 층 사이에 있는 정차 지점은 노드에 `level: 1.5`처럼 소수 높이를 준다.
- 그 지점이 어느 관의 어느 층과 이어지는지는 **도면이나 현장에서 확인한 뒤** 아래 표를 채운다. 확인하기 전에는 추측하지 않고 `unknown`에 적는다.

| 계단 정차 지점 | level | 이어지는 곳 | 근거 |
|---------------|-------|------------|------|
| (확인 필요) | | | |

## 관 사이 연결

관과 관을 잇는 복도는 어느 한쪽 파일의 `edges`에 적는다. 같은 층 도면(같은 `image`, 같은 `metersPerUnit`)이면 길이를 좌표로 계산하므로 `lengthM`이 필요 없다.

## 검사 항목(validate-graph)

- 파일 이름, 관·층 코드, `level`, `metersPerUnit`, 필수 배열
- ID 형식과 중복, 방 ID와 파일의 관·층이 맞는지
- edge 양 끝 노드가 있는지, 좌표 체계가 다른 파일과 잇는 edge에 `lengthM`이 있는지
- 계단·엘리베이터 group이 한 종류인지, 같은 높이가 두 번 나오지 않는지
- 모든 방 문이 입구에서 도달 가능한지(입구가 하나 이상 있을 때)
